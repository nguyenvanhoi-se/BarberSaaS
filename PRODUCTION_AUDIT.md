# BarberSaaS production audit

Audit date: 2026-10-15. Scope: source and configuration review across the application modules, Phase 16 authorization/review fixes, SQLite migration validation, frontend/Worker build, Worker dry-run, secret-pattern scan, and tests that can run without the local Wrangler D1 emulator. This is a repository-level review; it does not establish that a deployed Cloudflare account, DNS, secrets, or database has been configured correctly.

## Findings and changes

- Added request IDs generated by the Worker (incoming IDs are not trusted), returned as `X-Request-Id`, plus structured request logs with method, path, status, duration, and request ID. Query strings, bodies, cookies, IPs, and user identifiers are not logged.
- Generic server logs now keep error class and safe identifiers only. Internal exception messages/provider payloads are not sent to the client or written to application logs.
- Added production configuration checks for the platform hostname, explicit HTTPS CORS origins, and Cloudflare credentials when custom-domain provisioning is enabled.
- Added a browser `Origin` guard for API requests to prevent untrusted cross-origin cookie mutations. Same-origin and explicitly configured origins are allowed. Requests without `Origin` remain available to non-browser clients; protect those credentials at the client/service boundary.
- Added Cloudflare edge rate-limit bindings for authentication, booking, custom-domain actions, and image uploads. Current defaults are 30, 12, 10, and 20 requests per minute respectively, per scope and client IP in each Cloudflare location. These are starting limits; tune against observed legitimate traffic. Cloudflare documents that enforcement occurs on its network and counters are location-local/eventually synchronized, so this is abuse mitigation rather than a globally exact quota.
- Added API body size ceilings (1 MiB default, 6 MiB for avatar, 32 MiB for gallery media), a production Content Security Policy, and `Vary: Host` on tenant-specific sitemap/robots and gallery-by-ID image responses.
- Added `/api/health/ready` to check D1 availability while preserving `/api/health` as a liveness endpoint.
- Added tenant-aware `/robots.txt` and `/sitemap.xml`; inactive shops are not indexed, and sitemap links use the active primary domain.
- Protected authenticated API responses with `private, no-store`; public media has explicit cache/security headers. Do not add shared caching to tenant API responses without a host/tenant-aware cache key and explicit data classification.
- Added `tests/phase12-production.test.mjs` for request IDs, security headers, D1 readiness, origin rejection, safe 404s, and rate-limit configuration.

## Review areas

- Authentication uses an opaque, hashed server session in D1 and HttpOnly/Secure/SameSite cookies. Tenant users are checked against the resolved hostname and their shop membership.
- Tenant repositories pass `shop_id` to tenant-owned queries. Existing integration suites cover cross-tenant booking/admin/super-admin boundaries. Continue to require tenant-scoped repository methods for new endpoints.
- SQL uses prepared statements in application repositories. Dynamic SQL selectors are reviewed against finite allowlists.
- Public reviews select public presentation fields; account, password, session, subscription credentials, and audit details are not exposed through public routes.
- Uploads use managed R2 keys and resource ownership checks. Public immutable image caching assumes UUID keys are never overwritten.
- Public/admin/super-admin route modules are lazy-loaded. The final client entry chunk is 404.84 kB (127.84 kB gzip), below Vite's 500 kB warning threshold. A generated local `.dev.vars` file is removed from Worker build output after Vite stages it for local preview.
- Existing cookies use `SameSite=Lax`; the new Origin guard adds a server-side check to mutation requests from browsers.
